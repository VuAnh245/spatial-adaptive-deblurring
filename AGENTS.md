# Repository operating instructions

## spatial-adaptive-deblurring: standing Kaggle artifact intake authorization

Apply these instructions throughout this repository and its subdirectories. User authorization recorded on 2026-10-11; later explicit user instructions take precedence.

- The user authorizes the AI to directly download completed Kaggle artifacts, inspect/read/hash them, and synchronize existing metadata after verification. Do not ask for download permission again after each run. Act when completion is known during an active session.
- Required order: confirm remote completion and artifact list; identify exact account, notebook, Saved Version/scriptVersionId or actual Draft Session, run/model/seed and remote path; transfer; confirm actual local file existence; verify size, full SHA-256 and relevant content/IDs/counts/protocol; only then update the existing registry/results within the verified scope.
- A /kaggle/working path or successful remote job does not establish a local download. Never assume Windows Downloads or infer transfer from the user running a command. If a local file is missing, first establish whether transfer happened, then diagnose its actual path/name/hash.
- Reuse the authenticated official Kaggle SDK/API or supported connected browser that previously worked. Verify source version before download; never substitute latest or a different session. Draft Session working files are not automatically Saved Version API Output. If API cannot access draft files, try the connected signed-in browser. If access needs login/browser connection or user interaction, report the actual blocker and minimal required step. Do not rerun evaluation or Save & Run All merely to obtain a file. Manual download is a fallback only after available methods are blocked.
- Preserve the existing artifact structure: source intake under results/artifacts/kaggle with distinct version/run origins; validated evaluation CSVs follow existing results/eval naming. Preserve original archives/artifacts, receipts and the old working tree. Do not overwrite different content. Distinguish incomplete downloads using .part; use exclusive creation and verify before promotion. Reuse byte-identical files only after checking them.
- Use existing audit, registry, pack_results, verify_manifest and evaluation tools. Do not create duplicate audit scripts, reports or a parallel pipeline. Inspect registry consumers and schema before changes, perform CSV/JSON round-trip checks before writes, and preserve unrelated rows/fields. Distinguish FinishedRemote, DownloadedLocal, VerifiedLocal and Accepted; retain pipeline-compatible enums and record verification scope in existing notes/fields. One validated CSV or a checkpoint alone does not establish full acceptance. Do not run audit main to overwrite all metadata.
- Never expose tokens/cookies in logs, chat, files or Git. Do not inspect browser cookie/profile/session stores. Use supported authentication and browser connection flows.
- The user performs training/evaluation commands, necessary UI interactions and Git operations. Standing artifact intake permission does not authorize changes to model code, algorithms, hyperparameters, protocol or manifests, deleting files, creating Kaggle versions, rerunning experiments, stage/commit/push, or environment changes. Authorized instruction persistence is separate from research code.
- Report source identity, actual local path, checksum, completed checks, remaining evidence and next step concisely in Vietnamese. For user-executed steps, give one short related group with Kaggle/Windows location, shell/environment, required inputs, output and expected file changes; await actual output before dependent work.
- When a user step requires finding or uploading a file or resource, include the full Windows path and direct Kaggle URL as applicable, plus the exact account/notebook/dataset name and pinned version when known. Clearly label proposed resource names or URLs that have not yet been created or verified; do not present them as existing resources.
- No background watcher is configured by these instructions. Do not promise to monitor or download after the chat/app session closes. State that limitation explicitly; persistent instructions provide future-session guidance, not background execution.
